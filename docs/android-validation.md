安装的就是上述交付 Release APK。环境为隔离 x86_64 模拟器：Android 10 / API 29 与 Android 15 / API 35，均使用系统 WebView 124.0.6367.219。

| --- | --- | --- |
| Android 10 / API 29 | 通过 | 通过 |
| Android 15 / API 35 | 通过 | 通过 |

每个系统的主测试记录为 `OK (6 tests)`（其中覆盖安装检查需单独参数启用），随后独立执行覆盖安装检查，记录为 `OK (1 test)`。

验收包含真实 SQLite 和应用私有文件、账号创建/切换/隔离、所有记录类型、颜色库、不可变日历快照、本地图片 Canvas 取色、超过 CursorWindow 单行容量的资料、旧修订写入拒绝、重建 Activity 后持久化，以及原生网络层与生产电脑服务的双向同步和图片校验。

实际 WebView 界面通过真实触摸打开相机入口，接收原图、保存单品并重新读取。相机返回文件与系统文件选择器结果由 Espresso 提供受控文件，验证调用、权限 URI、数据传递和原图保存链路；没有把它当作物理相机或用户手动操作的验收。

ZIP 使用原生流式导出、系统选择器返回文件、SHA-256 核对、原图恢复，并通过真实移动端适配器创建新的衣橱、保留记录 ID。覆盖安装测试先强制停止进程，再用 `adb install -r` 安装相同签名 APK，随后检查之前创建的记录仍保存在全部衣橱中。

原始结果在 `.test-runtime/android-results/` 的 `emulator-5574-*`（API 29）及 `emulator-5570-*`（API 35）文件。

Android 10 的出厂 WebView 74 无法运行界面依赖，已验证 App 显示明确的更新说明，更新至 124 后运行正常。API 29 镜像最初没有配置 ART 堆增长上限，默认 16 MB 导致大文档验收内存不足；测试环境配置为 192 MB 后重新验证。这里没有声称通过 16 MB 堆环境或低内存压力验收。
